# vpnmax 强制更新与 UDP 跳跃订阅

## 症状

`deploy_singbox.sh --force` 执行后，服务器日志显示重新安装，但旧 `/usr/bin/sb` 仍被保留；订阅中 HY2/TUIC 的 `ports` / `mport` 为空。防火墙 DNAT 规则却看起来正常。

## 根因

1. `--force` 只打印提示，既有 `sb.sh` 仍进入哈希复查；历史 Argo 补丁 marker 被当成当前可信版本，导致新 vendor 永远不覆盖旧文件。
2. 订阅生成从 `iptables-save` 读取跳跃段时，最初只匹配了 `--dports`；本项目 Ubuntu 服务器真实输出是 `--dport 40000:42000`，所以解析仍为空。
3. 端口跳跃规则存在不等于订阅可用；必须分别验证实际脚本哈希、订阅字段和真实客户端握手。

## 修复

- `--force` 现在强制进入安装分支；可信哈希只认当前原版与当前 Argo 补丁版，历史 marker 仅作审计。
- 安装使用同目录暂存、哈希校验、原子替换，失败不把旧非空文件误判成成功。
- 跳跃段提取同时兼容 `--dport` 与 `--dports`。
- 端口跳跃日志把 `40000:42000` 正确显示为 `40000-42000`。

## 验证

QQ/QQ2 真机强制重跑后：

- `/usr/bin/sb` 哈希为当前 Argo 补丁版；
- `clmi.yaml` 同时出现 `ports: 40000-42000` 与 `ports: 43000-45000`；
- `jhsub.txt` 的 HY2/TUIC 链接分别包含对应 `mport`；
- sing-box 服务保持 active；
- 最后仍需在用户实际客户端刷新订阅并完成 HY2/TUIC 真实握手，不能用服务器本机检查替代。

## 教训

“代码已 push”“防火墙规则已存在”“脚本显示部署完成”都不能单独证明用户侧已修复。更新链必须验证最终产物。
